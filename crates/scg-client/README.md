# scg-client

Client library for the Secure Communication Gateway's **local interfaces** —
how a co-located application attaches to the gateway without touching a
network socket. One synchronous Rust core drives two transports:

- **UDS** — a framed byte pipe over a Unix-domain socket.
- **SHM** — a sealed two-ring shared-memory channel with `eventfd` wakeups
  (zero-copy send via reserve/commit is available).

The endpoint itself is provisioned by the gateway's gRPC management API (this
library performs that call for you); the gateway then bridges the local
endpoint onto its secured network leg. Contracts:
[docs/interfaces/09-configuration.md](../../gateway/docs/interfaces/09-configuration.md)
and [10-management-api.md](../../gateway/docs/interfaces/10-management-api.md).

## Building

```bash
cargo build -p scg-client --release
```

produces, under `target/release/`:

| Artifact | Use |
|---|---|
| `libscg_client.so` | C/C++ via the C ABI (`cdylib`) |
| `libscg_client.a` | static linking (`staticlib`) |
| rlib | Rust programs (`scg-client` as a dependency) |

The C header `include/scg_client.h` (and a thin C++ wrapper
`include/scg_client.hpp`) are generated by `cbindgen` at build time from the
`extern "C"` surface.

## Using it from C/C++

```bash
cc -Wall -O2 -I crates/scg-client/include \
   your_app.c -L target/release -lscg_client -lpthread -ldl -o your_app
LD_LIBRARY_PATH=target/release ./your_app ...
```

Worked examples live in [`examples/`](examples/): `c/` (plain send/recv),
`cpp/`, a zero-copy SHM sender (`c/zero_copy.c`), and a Rust round-trip
(`examples/rust_roundtrip.rs`). `examples/Makefile` builds them against a
prior `cargo build -p scg-client`.

## Trying it end to end

`../../scripts/run_local_clients.sh` is the unprivileged smoke test: it builds
the gateway, a TLS echo upstream, and the Rust/C/C++ example clients, then
drives a send/recv round trip with each client over both UDS and SHM against a
real gateway.

## Security notes

- Endpoint attachment is authenticated by a **single-use capability token**
  handed out at provisioning time, plus `SO_PEERCRED` uid checks; treat the
  token like a secret (the library never logs it).
- The gateway→client SHM ring is sealed (`F_SEAL_WRITE`), so a client maps it
  read-only and cannot tamper with gateway memory.
